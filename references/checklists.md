# Чек-листы аудита проектов в Redmine

## Чек-лист структуры проекта

- [ ] Проект имеет чёткое название и идентификатор
- [ ] В проекте настроены Версии (Versions/Milestones)
- [ ] Задачи привязаны к конкретным версиям
- [ ] В проекте настроены Категории (Components)
- [ ] Используются разные Трекеры (Bug, Feature, Task, Support)
- [ ] Настроены кастомные поля для нужд проекта
- [ ] У проекта есть описание и видение (description)
- [ ] Назначены роли участникам (менеджер, разработчик, тестировщик)

## Чек-лист качества задач

- [ ] У каждой задачи есть описание (не пустое, > 20 символов)
- [ ] Описание содержит контекст и цель задачи
- [ ] У задачи указан критерий выполнения (Definition of Done)
- [ ] У задачи назначен исполнитель (Assignee)
- [ ] У задачи указан приоритет, соответствующий важности
- [ ] У задачи указан трекер, соответствующий типу работы
- [ ] У задачи установлена дата начала (start date)
- [ ] У задачи установлен крайний срок (due date), если применимо
- [ ] У задачи указана оценка трудоёмкости (estimated hours)
- [ ] У задачи есть связи с другими задачами, если есть зависимости
- [ ] У задачи есть родительская задача или подзадачи, если применимо

## Чек-лист коммуникации

- [ ] При смене статуса оставляется комментарий с пояснением
- [ ] В задачах видна активная переписка по уточнению требований
- [ ] Комментарии содержат конструктивную информацию (не просто "в работе")
- [ ] Менеджер отвечает на вопросы команды в разумные сроки (< 1 рабочего дня)
- [ ] Важные решения зафиксированы в комментариях, а не только в устной форме
- [ ] При переназначении задачи указана причина

## Чек-лист динамики проекта (за неделю)

- [ ] Было создано новых задач: __ (ожидаемо: > 0)
- [ ] Задач переведено в статус "Выполнено": __ (ожидаемо: > 0)
- [ ] Задач обновлено с комментариями: __ (ожидаемо: > 0)
- [ ] Среднее время реакции на новую задачу: __ часов (норма: < 24ч)
- [ ] Количество застрявших задач (в работе > 7 дней): __ (норма: 0-2)
- [ ] Количество задач без назначенного исполнителя: __ (норма: 0)
- [ ] Записано часов в Time Tracking: __ (ожидаемо: > 0 если используется)
- [ ] Среднее время выполнения задачи: __ дней

## Чек-лист бэклога

- [ ] Общее количество открытых задач: __ (красная зона: > 50)
- [ ] Количество задач без приоритета: __ (норма: 0)
- [ ] Количество задач без категории: __ (норма: < 10%)
- [ ] Задачи старше 6 месяцев без движения: __ (норма: 0)
- [ ] Распределение по приоритетам: Высокий __, Средний __, Низкий __
- [ ] Распределение по статусам: Новая __, В работе __, Решена __, Закрыта __

## Чек-лист назначений и загрузки

- [ ] У каждой активной задачи назначен исполнитель
- [ ] Нагрузка распределена равномерно между командой
- [ ] Нет перегруженных исполнителей (> 5 задач "В работе")
- [ ] Нет задач, назначенных на недоступных сотрудников
- [ ] Менеджер не является исполнителем всех задач (делегирование)

## Чек-лист учёта времени

- [ ] В проекте включён модуль Time Tracking
- [ ] Задачи имеют estimated hours (плановая оценка)
- [ ] Исполнители логируют затраченное время
- [ ] Плановая оценка и факт расходуются сходимостью ±30%
- [ ] Видна динамика burned hours vs estimated hours
