# Примеры отчётов аудита

## Пример 1: Отчёт с оценкой B (Хорошо)

```markdown
# Аудит проектов — 2026-06-09

## Обзор
- Проектов проверено: 2
- Период: 2026-06-02 — 2026-06-08
- Общая оценка: 82/100 (B — Хорошо)

---

## Проект: "Мобильное приложение Банк-Клиент"
### Оценка: 85/100 (B)

#### Что делается хорошо
- Регулярное обновление статусов: в течение недели 23 задачи получили
  комментарии с прогрессом. Менеджер ежедневно мониторит активность.
- Чёткая структура: задачи разбиты на версии v2.3.0 (спринт) и v2.4.0 (бэклог).
- Корректное использование трекеров: баги отделены от фич (Bug vs Feature).
- Балансировка нагрузки: задачи распределены между 4 разработчиками
  (avg 3.2 задачи "В работе" на человека).

#### Что требует улучшения
- **PM-MAJ-02** (Коммуникация): 4 задачи (#1847, #1851, #1856, #1862) переведены
  в статус "Решена" без комментариев. Исполнители не объяснили, что именно было сделано.
  *Рекомендация*: Внедрите обязательное правило — при смене статуса на "Решена"
  требуется комментарий с перечислением выполненных действий. Срок: до 12 июня.

- **PM-MIN-01** (Неполные данные): У 7 задач отсутствует due date, хотя
  относятся к версии v2.3.0 с дедлайном 15 июня.
  *Рекомендация*: Проставьте due date для всех задач версии v2.3.0,
  исходя из даты релиза. Срок: до 10 июня.

- **PM-MIN-03** (Неактуальные данные): Задача #1799 назначена на
  Иванова С. (уволился 20 мая). Задача всё ещё в статусе "В работе".
  *Рекомендация*: Переназначьте задачу #1799 на другого разработчика
  и обновите оценку трудоёмкости. Срок: немедленно.

#### Рекомендации
1. **На этой неделе**: Настройте обязательный комментарий при переводе
   задачи в статус "Решена". Это улучшит прозрачность для QA-команды.
2. **На этой неделе**: Проведите аудит назначений — уберите уволенных
   сотрудников, перебалансируйте нагрузку.
3. **В ближайший спринт**: Добавьте due date для всех задач текущего спринта
   и настройте автоматические напоминания за 2 дня до дедлайна.

---

## Проект: "API Интеграция с платёжной системой"
### Оценка: 78/100 (B)

#### Что делается хорошо
- Хорошая документированность: задачи содержат подробные описания
  со ссылками на API-документацию партнёра.
- Активное использование журналов: среднее 3.4 комментария на задачу.
- Учёт времени: 87% задач имеют logged time, средняя точность оценки ±22%.

#### Что требует улучшения
- **PM-CRIT-03** (Застрявшие задачи): 3 задачи (#1901, #1904, #1908) находятся
  в статусе "В работе" более 10 дней без комментариев.
  *Рекомендация*: Проведите 15-минутный stand-up с исполнителями, выясните
  причины задержек. Обновите статусы или разбейте задачи на меньшие.
  Срок: 10 июня.

- **PM-MAJ-04** (Типы задач): Все 34 задачи используют трекер "Задача",
  не разделяя баги и фичи.
  *Рекомендация*: Внедрите трекеры Bug и Feature. Переклассифицируйте
  существующие задачи. Срок: до конца спринта (16 июня).

#### Рекомендации
1. **Немедленно**: Разблокируйте задачи #1901, #1904, #1908 — проведите
   stand-up и обновите статусы с комментариями.
2. **На этой неделе**: Настройте трекеры Bug и Feature для проекта,
   начните классифицировать новые задачи правильно.
3. **Стратегически**: Внедрите ежедневный 10-минутный stand-up для раннего
   выявления блокеров.
```

## Пример 2: Отчёт с оценкой D (Ниже среднего)

```markdown
# Аудит проектов — 2026-06-09

## Обзор
- Проектов проверено: 1
- Период: 2026-06-02 — 2026-06-08
- Общая оценка: 48/100 (D — Ниже среднего)

---

## Проект: "Корпоративный портал"
### Оценка: 48/100 (D)

#### Что делается хорошо
- Менеджер создаёт задачи регулярно (12 новых за неделю).
- Используются приоритеты (High/Medium/Low) корректно.
- Версии настроены: v1.0 (текущая) и Backlog.

#### Что требует улучшения
- **PM-CRIT-01** (Структура): 67 открытых задач без разделения на подсистемы.
  Нет категорий (Components), нет родительских задач для крупных фич.
  *Рекомендация*: Разбейте задачи по модулям портала
  (Авторизация, Новости, Документы, Профиль). Создайте эпики для
  крупных функций. Срок: 13-14 июня.

- **PM-CRIT-02** (Описания): 41 задача (61%) имеет описание < 30 символов
  или пустое. Примеры: #2041 "Исправить баг", #2056 "Доработка формы",
  #2078 "Не работает" — невозможно понять, что ожидается в результате.
  *Рекомендация*: Внедрите шаблон описания задачи:
  (1) Что нужно сделать, (2) Зачем, (3) Критерии приёмки.
  Обновите описания для 10 приоритетных задач. Срок: до 12 июня.

- **PM-CRIT-05** (Учёт времени): 0 задач имеют logged time.
  Estimated hours не заполнены ни в одной задаче.
  *Рекомендация*: Начните с оценки трудоёмкости для всех задач версии v1.0.
  Обучите команду логировать время ежедневно (15 минут в конце дня).
  Срок: начать 11 июня.

- **PM-MAJ-01** (Статусы): 23 задачи в статусе "Новая" более 5 дней
  без реакции. 8 задач в статусе "Решена", но не проверены QA.
  *Рекомендация*: Введите SLA — новая задача должна быть оценена
  и назначена в течение 24 часов. Закрывайте задачи только после QA.
  Срок: немедленно.

- **PM-MAJ-03** (Назначения): 34 задачи (51%) не назначены ни на кого.
  Из назначенных — 80% на одного разработчика (Петров А.).
  *Рекомендация*: Распределите неназначенные задачи между командой
  (5 человек). Снимите перегрузку с Петрова А. (сейчас 18 задач "В работе").
  Срок: 10 июня.

- **PM-MIN-04** (Бэклог): 12 задач созданы более 6 месяцев назад,
  не обновлялись. Скорее всего, неактуальны.
  *Рекомендация*: Проведите бэклог-груминг — закройте неактуальные
 задачи с пометкой "won't fix", переприоритизируйте остальные.
  Срок: 13 июня.

#### Рекомендации (по приоритету)
1. **Немедленно**: Распределите задачи между командой, снимите
   перегрузку с Петрова А. Назначьте ответственного за QA-верификацию.
2. **До 12 июня**: Внедрите шаблон описания задачи, обновите
   описания для 10 приоритетных задач.
3. **До 14 июня**: Структурируйте проект по модулям, проведите
   бэклог-груминг.
4. **Неделя 11-16 июня**: Внедрите учёт времени, начните оценку
   трудоёмкости.
5. **Стратегически**: Внедрите Definition of Done для всех типов задач.
```

## Пример 3: Краткая сводка (еженедельная)

```markdown
## Weekly Review: 2 проекта | Общая оценка: B (82/100)

### Мобильное приложение — B (85/100)
✅ Хорошо: регулярные обновления, структура по версиям, баланс нагрузки
⚠️ Улучшить: комментарии при закрытии задач (4 шт. без комментов),
   due date для спринтовых задач

### API Интеграция — B (78/100)
✅ Хорошо: подробные описания, активные журналы, учёт времени (±22%)
⚠️ Улучшить: 3 застрявшие задачи (>10 дней), внедрить трекеры Bug/Feature

### Рекомендации на неделю:
1. Stand-up для разблокировки задач #1901, #1904, #1908
2. Настроить обязательные комментарии при смене статуса на "Решена"
3. Проставить due date для задач v2.3.0
4. Настроить трекеры Bug/Feature для API-проекта
```
